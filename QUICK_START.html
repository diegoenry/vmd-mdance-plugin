Getting Started

VMD Plugin

Open VMD, then go to Extensions > Analysis > MDANCE Clustering, or type in the VMD console:

package require mdance
mdance::gui
  1. Load a molecule with a trajectory in VMD.
  2. In the Setup tab, set the molecule ID (top for current) and an atom selection (e.g. protein and name CA).
  3. Click Preview to verify atom count and frame count.
  4. (Optional) Adjust Display Settings: set the app font size and the default plot font size.
  5. Select an algorithm tab, configure parameters, and click Run.
  6. Inspect results in the Results tab.

Command-Line Tool

mdance-cli --algorithm {kmeans|divine|helm} \
            --input coordinates.csv \
            --output results.json \
            --natoms <int> \
            --nclusters <int> \
            --metric MSD \
            [algorithm-specific options...]
The --natoms parameter Number of atoms per frame. Normalizes MSD so results are comparable across systems of different sizes. For general (non-MD) data, set --natoms 1.

Input & Output Formats

Coordinate CSV (Input)

Each row is one frame. Each column is a coordinate value. For N atoms, each row has 3N columns (x1, y1, z1, x2, y2, z2, …). No header row. The VMD plugin generates this automatically.

1.234,5.678,9.012,3.456,...
1.240,5.690,9.001,3.461,...

Result JSON (Output)

FieldDescription
algorithmAlgorithm name (kmeans, divine, or helm)
nFramesTotal frames processed
nClustersFinal cluster count
labelsCluster assignment for each frame (array of integers)
clusterSizesNumber of frames in each cluster
representativesMedoid (most central) frame index per cluster
clusterMSDWithin-cluster mean square deviation (compactness)
scoresCalinski-Harabasz and Davies-Bouldin indices
zMatrixDendrogram linkage matrix (HELM only)

KMeans NANI

K

KMeans with NANI Initialization

Partitional
How it works: Assigns every frame to the nearest of K cluster centers, recomputes centers as the mean of assigned frames, and repeats until convergence. NANI provides intelligent initialization strategies that consistently outperform random seeding.
When to use: When you know (or want to specify) the number of clusters and need fast results. Best for an initial exploratory pass.

Parameters

ParameterCLI FlagValuesDefaultDescription
Number of clusters--nclusters2 – 200requiredHow many clusters to create. Start with the expected number of conformational states.
Metric--metricSee metricsMSDDistance function. MSD is standard for atomic coordinates.
Initialization--kinitSee belowStratAllHow initial cluster centers are chosen. Strongly affects quality and reproducibility.
Sampling %--percentage1 – 10010Fraction of data used during initialization. Higher = more robust but slower.

Initialization Strategies (--kinit)

StrategyDescriptionWhen to use
CompSimIdentifies high-density regions via complementary similarity, then selects diverse centers.Recommended. Most robust for MD trajectories.
StratAllStratified sampling across the full dataset; first K points become centers.Good general-purpose choice. Fast.
StratReducedStratified sampling on the high-density subset only.When data has many outlier frames.
DivSelectPure diversity selection. Maximizes spread of initial centers.When clusters are expected to be well-separated.
KmeansPPGreedy K-means++ (Arthur & Vassilvitskii).Industry-standard. Slightly slower than Strat methods.
VanillaKmeansPPStandard (non-greedy) K-means++.When KmeansPP is too aggressive.
RandomRandom center selection.Baseline comparison only.

Example

mdance-cli --algorithm kmeans \
    --input trajectory.csv \
    --output kmeans_result.json \
    --natoms 352 \
    --nclusters 10 \
    --metric MSD \
    --kinit CompSim \
    --percentage 10

DIVINE

D

Divisive Hierarchical Clustering

Top-Down Hierarchical
How it works: Starts with all frames in one cluster. At each step, selects the cluster with the highest internal variance (by split criterion), splits it into two sub-clusters using anchor points, and repeats until the target count is reached. Optionally refines with KMeans.
When to use: When you want a hierarchical decomposition of the trajectory, or when the natural number of clusters is unknown and you want to observe how data splits.

Parameters

ParameterCLI FlagValuesDefaultDescription
Number of clusters--nclusters2 – 200requiredTarget number of clusters.
Metric--metricSee metricsMSDDistance function.
Split criterion--splitSee belowWeightedMSDHow to score clusters for splitting (which one to split next).
Anchor method--anchorsSee belowNANIHow to choose the two seed points when splitting.
Initialization--kinitSame as KMeansStratAllUsed for refinement step only (when --refine is set).
Refine--refineflagoffApply KMeans refinement after splitting. Produces cleaner boundaries. Recommended.
Threshold--threshold0.0 – 1.00Minimum cluster size as fraction of total. 0.2 = won't split clusters below 20%.
End mode--end-modek, pointskk: stop at K clusters. points: keep splitting to individual frames.
Sampling %--percentage1 – 10010Fraction of data used during anchor selection and initialization.

Split Criteria (--split)

CriterionDescriptionWhen to use
WeightedMSDMSD weighted by cluster size. Balances splitting large and high-variance clusters.Recommended. Most stable across datasets.
MSDRaw mean square deviation. Always splits the highest-variance cluster.When variance is the primary concern.
RadiusMaximum distance from center to any member.When spatial extent matters more than variance.

Anchor Methods (--anchors)

MethodDescriptionWhen to use
NANIUses complementary similarity and diversity selection for two representative anchors.Recommended. Most robust; avoids outlier-driven splits.
OutlierPairSelects the two most dissimilar points as anchors.When clusters are well-separated and outliers are informative.
SplinterPairSelects points at the cluster periphery.Alternative when OutlierPair produces uneven splits.

Example

mdance-cli --algorithm divine \
    --input trajectory.csv \
    --output divine_result.json \
    --natoms 352 \
    --nclusters 5 \
    --metric MSD \
    --split WeightedMSD \
    --anchors NANI \
    --refine \
    --threshold 0.1 \
    --end-mode k \
    --percentage 10

HELM

H

Hierarchical Agglomerative Linkage Merging

Bottom-Up Hierarchical
How it works: Starts from initial clusters (typically from KMeans pre-clustering) and iteratively merges the two most similar clusters until a stopping criterion is met. Produces a dendrogram showing the full merge history. Includes trimming options.
When to use: When you want to merge an existing partition into coarser clusters, need a dendrogram, or when the dataset has outlier frames that need trimming.

Parameters

ParameterCLI FlagValuesDefaultDescription
Number of clusters--nclusters0 – 20010Target cluster count. Set to 0 to use epsilon-based stopping.
Metric--metricSee metricsMSDDistance function.
Merge scheme--merge-schemeSee belowInterLinkage criterion for deciding which clusters to merge.
Epsilon--eps> 0 or -1-1Distance threshold. Merging stops when all distances exceed this. -1 = disabled.
Initial labels--initial-labelsCSV pathautoPre-computed cluster labels. If omitted in VMD, KMeans pre-clustering runs automatically.
Trim start--trim-startflagoffEnable trimming of initial clusters before merging.
Min samples--min-samples0.0 – 1.00.01Minimum population fraction. 0.01 = clusters below 1% of frames are removed.
Trim value--trim-val≥ 00Maximum allowed within-cluster MSD. 0 = disabled.
Trim K--trim-k≥ 00Remove the K most diffuse initial clusters. 0 = disabled.

Merge Schemes (--merge-scheme)

SchemeDescriptionWhen to use
InterMerges clusters with smallest between-cluster distance (single-linkage style).Recommended. Finds well-separated clusters.
IntraMerges clusters producing smallest within-cluster variance increase (Ward-like).When you want compact, equally-sized clusters.
HalfHybrid of Intra and Inter.When neither pure approach works well.

Stopping Criteria

Two mutually exclusive modes:

ModeSettingsBehavior
K-based--nclusters N --eps -1Merge until exactly N clusters remain.
Distance-based--nclusters 0 --eps VALUEMerge until all pairwise distances exceed VALUE.

Trimming

Trimming removes problematic initial clusters before the main merging phase. Enable with --trim-start and configure with:

  • --min-samples 0.025 — Remove clusters with < 2.5% of total frames (noise clusters).
  • --trim-val 5.0 — Remove clusters with internal MSD > 5.0 (diffuse clusters).
  • --trim-k 3 — Remove the 3 most diffuse clusters (simple, size-independent).
Tip These options can be combined. Trimming is especially useful when pre-clustering produces many tiny or scattered clusters.

Pre-Clustering

HELM requires an initial partition. Two approaches:

  • Automatic (VMD plugin default): Runs KMeans with K=50. Configurable via the “Pre-cluster K” spinbox.
  • Manual: Provide a labels CSV via --initial-labels. One label per line, or two columns (frame index, label).

Example: K-based stopping

mdance-cli --algorithm helm \
    --input trajectory.csv \
    --output helm_result.json \
    --natoms 352 \
    --nclusters 8 \
    --metric MSD \
    --merge-scheme Inter \
    --initial-labels kmeans_labels.csv

Example: Epsilon stopping with trimming

mdance-cli --algorithm helm \
    --input trajectory.csv \
    --output helm_result.json \
    --natoms 352 \
    --nclusters 0 \
    --eps 15.0 \
    --metric MSD \
    --merge-scheme Inter \
    --trim-start \
    --min-samples 0.025 \
    --trim-k 2 \
    --initial-labels kmeans_labels.csv

Distance Metrics

All three algorithms accept a --metric parameter. The choice depends on data type.

MetricFull NameBest For
MSDMean Square DeviationAtomic coordinates (default). Euclidean-family, normalized by atom count. Use this for MD.
BUBBaroni-Urbani-BuserBinary fingerprint data.
FaiFaithBinary fingerprint data.
GleGleasonExtended similarity for mixed data.
JaJaccardBinary presence/absence data. Ignores joint absences.
JTJaccard-TanimotoChemical fingerprint similarity. Standard in cheminformatics.
RTRogers-TanimotoBinary data. Penalizes mismatches more than Jaccard.
RRRussel-RaoBinary data. Considers only joint presences.
SMSokal-MichenerBinary data. Treats presences and absences symmetrically.
SS1Sokal-Sneath 1Binary data. Variant of Jaccard.
SS2Sokal-Sneath 2Binary data. Variant of SM.
For MD trajectory clustering, use MSD. The other metrics are designed for binary or fingerprint-based data representations.

Quality Scores

Every clustering run reports two quality metrics.

Calinski-Harabasz Index (CH)

Ratio of between-cluster dispersion to within-cluster dispersion.

  • Higher is better. Dense clusters that are well-separated from each other.
  • Useful for comparing different K values on the same dataset.
  • Not comparable across different datasets.

Davies-Bouldin Index (DB)

Average similarity ratio between each cluster and its most similar neighbor.

  • Lower is better. Compact clusters far from each other.
  • Less sensitive to cluster count than CH.
  • Values close to 0 indicate excellent separation.
Choosing K with the Elbow Plot Use the Elbow Plot visualization to plot CH and DB across a range of K values. Look for a peak in the CH curve (maximum ratio) and a valley in the DB curve (minimum overlap).

Visualizations

Available from the Results tab after running any algorithm. Organized in two rows of buttons.

Plot Window Features

Every plot window includes an interactive toolbar:

  • Font size spinner — adjust text size within the figure (per-window setting)
  • Export CSV — save the underlying data (cluster IDs, scores, distances, etc.) as a comma-separated file
  • Export PS — save the figure as PostScript (always available)
  • Export PNG — save the figure as PNG (requires ImageMagick or GraphicsMagick; falls back to PostScript if unavailable)

All plot windows auto-resize: drag the window border and the figure redraws to fill the new dimensions. Computationally expensive plots (Silhouette, Distances, Rep. RMSD, Dendrogram) cache their results so resizing is fast.

Algorithm Selection Guide

ScenarioRecommendedReasoning
Quick exploration of a new trajectoryKMeans NANIFast, simple, immediate results. Use Elbow Plot to determine K.
Unknown number of conformational statesDIVINEHierarchical splitting reveals natural structure. Use threshold to control minimum cluster size.
Refining a coarse partitionHELMMerges over-split clusters while preserving meaningful distinctions.
Noisy trajectory with outliersHELM + trimmingTrim options remove noise clusters before merging.
Dendrogram visualization neededHELMHELM produces a native Z-matrix for exact merge history. KMeans/DIVINE also show post-hoc dendrograms from centroid distances.
Reproducibility across runsKMeans + CompSimCompSim initialization is deterministic given the same data.
Very large trajectories (>10K frames)KMeans NANIO(n·k·i) scales well. HELM is O(k²) on initial clusters only.
Coarse-to-fine pipelineKMeans → HELMKMeans for fast initial partition, HELM for hierarchical refinement.
